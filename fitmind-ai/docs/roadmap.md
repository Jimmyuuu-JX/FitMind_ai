## 1. 目标

把 FitMind AI 从「规则驱动、模型点缀」做成说明书描述的样子：**训练日志扎实，教练由模型主导、事实由计算层把关**，先让几个人到几十人能安心长期使用，同时不堵死之后扩大的路。

---

## 2. 顺序总览

| 阶段 | 内容                     | 为什么排在这里                                             |
| ---- | ------------------------ | ---------------------------------------------------------- |
| 0    | 摸清现状、清理、文档对齐 | 低风险；不先做，后面每一步都在过时信息和死代码上动         |
| 1    | 教练重做为模型主导       | 定位的核心，也是当前体验与定位差距最大的地方               |
| 2    | 健康数据接入教练         | 依赖阶段 1 的工具循环；涉及敏感数据，单独成段、单独验收    |
| 3    | 录入解析改为模型为主     | 高频入口；与阶段 1 共用提供方接缝，可在阶段 1 稳定后并行   |
| 4    | 让几个人安心长期用       | 账户自助、数据安全和可恢复性；其中标注「可提前」的不必等   |
| 5    | 扩大规模前的门槛         | 不按时间排期，按触发条件启动                               |

阶段 0 之后，阶段 4 中标注「可提前」的条目可以随时穿插；阶段 1 内部的步骤有先后依赖，按编号做。

## 3. 阶段 0 — 摸清现状、清理、文档对齐

### 0.1 确认线上状态

两个实例各自确认：部署的提交、数据库迁移到哪一版、教练和录入实际使用的提供方与型号、调用预算配置。存档路线图里「在目标数据库执行个人工具迁移并做线上冒烟」这一项是否已完成，一并确认。

完成标准：两个实例的上述事实有本次读取的记录；与 `main` 不一致的地方列出并决定更新还是保留。

### 0.2 对齐进行中弧线的状态

`INDEX.md` 把实体解析弧线写成「ER-1C 起待做」，而 [`er-arc-plan.md`](./er-arc-plan.md) 把 ER-1C、ER-2、ER-3 各批标为已实现或待复核。逐批核对代码与测试，把两处改成一致；计划卡弧线的 PL-4（每个用户只有一个生效计划）仍待做，保留。

完成标准：`INDEX.md` 的「进行中的弧线」与各计划文档、代码三者一致。

### 0.3 清理

- 删除界面上已到不了的客户端代码：旧录入表单及其 hook、旧推荐面板及只被它使用的组件和 API 封装、旧助手状态栏与工具调用卡、只被自身测试引用的客户端洞察构建器和录入草稿模块。
- 两处写死的模型型号改为配置项。
- 生产路径上的 `mock` 命名（入口函数名、响应里的助手类型标记）改为与实际职责相符的名字。
- 同意表缺失时的迁移窗口兼容分支：确认两个实例都已完成迁移后删除。

完成标准：`pnpm verify` 与端到端测试通过；删除项在提交说明中逐个列出。

### 0.4 文档对齐

- [`architecture.md`](./architecture.md)：按现状重写部署结构和教练数据流（目前仍画着已不使用的托管方）。
- [`ai-decisions.md`](./ai-decisions.md)：决策与理由保留，去掉每条后面面向面试的小节。
- `project-study-guide.md`、`demo-script.md`：移入存档。
- `INDEX.md`：随上述变化更新入口。

完成标准：`docs/` 下除存档目录外不再有面向求职的内容；`INDEX.md` 的每个链接可达。

## 4. 阶段 1 — 教练重做为模型主导

目标形态见说明书第 5 节。按下面的顺序做，每一步单独可验收、可回退。

### 1.1 先立评测

现有评测是为规则路由写的确定性用例。扩成能对真实模型跑的评测集：覆盖同义改写、追问、需要多个工具才能回答的问题、应当拒答和应当分流的问题。离线门禁保持确定性、不联网；真实模型评测作为人工触发的单独命令。

完成标准：同一套用例能分别对规则路径和真实模型路径出分；作为后续每一步的回归基线。

### 1.2 对话带历史

请求携带本会话的近期消息；服务端已有会话与消息表，客户端补上会话的恢复与继续，关掉再打开能接着聊。历史长度有上限，超出部分的处理方式（截断或摘要）在决策记录里写明。

完成标准：追问类评测用例通过；刷新后会话可恢复；跨用户读取会话返回与不存在相同的结果。

### 1.3 多步工具循环

模型按需多次调用只读工具再作答。工具集从当前四个扩到覆盖分析页已有的口径（肌群负荷、计划依从度、动作知识检索等），每个工具返回计算结论和依据的数据点。循环有步数上限、单轮成本上限和超时，触顶时带着已有依据作答并说明。

完成标准：多工具评测用例通过；触顶路径有测试；每一步工具调用仍写入工具日志并在界面的依据区可见。

### 1.4 模型写解释，真实流式

答案正文由模型生成并逐段流式输出，取代模板拼接和「写完再切块发送」。数字核对保留：正文中的数值必须出现在本轮工具结果里，核对结果对用户可见；核对不通过时的处理（标注或退回降级答案）在决策记录里定。

完成标准：首字时间按说明书第 10 节的口径实测并记录；数字核对的正反用例通过。

### 1.5 规则层降级为兜底

关键词路由、兜底分类、强制工具调用和固定答案模板退出主路径，只在提供方不可用或预算用尽时启用，并保留为评测对照。伤痛与医疗的安全分流不在此列，继续放在模型之前。

完成标准：主路径不再经过关键词路由；断开提供方时仍能得到带依据的降级回答；安全分流用例全部通过。

### 1.6 周计划接入同一个教练

计划生成器保留为确定性工具（按器械与伤病过滤、负重取整等规则不交给模型），由教练在对话中调用；现有的「固定步骤、不调模型」的计划流程并入工具循环。计划仍以草稿形式交给用户编辑和接受。

完成标准：对话中提出的计划请求与结构化入口产出同一种草稿；接受前不落库。

### 1.7 对话里的写操作走草稿

「帮我记一下刚才练的」「把周三改成休息」这类请求，模型产出结构化草稿，复用现有的确认界面，由用户确认后落库。对话路径上仍然没有直接写库的工具。

完成标准：每种写操作都有「未确认则数据库无变化」的测试。

### 提供方

境内实例与海外实例可以用不同提供方，型号由配置决定。选型在 1.1 的评测集上比较后记入决策记录；选型本身不阻塞 1.2–1.3 的开发。

## 5. 阶段 2 — 健康数据接入教练

约束见说明书第 6 节。这是敏感数据改动，按 `AGENTS.md` 的高影响流程做，合入前需要独立复核。

- **同意闸门在服务端。** 教练的健康数据工具在执行时检查敏感健康数据同意的当前状态；未同意或已撤回时工具不可用，模型看不到这类数据，回答里明说没有这部分信息。
- **只读事实工具。** 身体数据返回记录值与趋势；经期返回用户记下的日期。不推算周期，不输出医学解读。
- **工具日志脱敏。** 当前工具日志保存完整的工具输入输出；健康数据工具的日志只记调用事实，不记具体数值。
- **删除联动。** 用户分类删除或全部删除健康数据后，教练不再引用；已保存的对话和洞察中引用过的内容如何处理，先定规则再实现。
- **界面告知。** 教练用到健康数据时，在依据区标明用了哪一类。

完成标准：未同意、已撤回、已删除三种状态各有服务端测试证明模型请求中不含健康数据；日志脱敏有测试；跨境实例的同意要求不被绕过。

## 6. 阶段 3 — 录入解析改为模型为主

- 语音和自由文本的解析以模型的结构化输出为主，现有规则解析器退为离线或提供方不可用时的兜底。动作匹配到词典、未匹配时让用户选择的流程不变，保存前确认不变。
- 用真实口语样本建一组解析评测（每组不同重量、先报清单再分述、单位混用等），替换前后对比。
- 合并重复的中文数字解析表。
- 训练中的草稿在本地持久化，刷新或误关后能恢复。

完成标准：解析评测上模型为主的路径不低于现有路径；断开提供方时规则兜底可用；草稿恢复有端到端测试。

## 7. 阶段 4 — 让几个人安心长期用

- **个人页的数据入口（可提前）。** 注销账号、分类删除健康数据的入口放到个人页；目前只在补签同意的页面里。
- **找回密码（可提前）。** 邀请制小规模下先定方式：维护者代为重置，或接入邮件发送。定了再做。
- **邀请管理。** 发邀请、看谁已注册、停用账户，目前靠脚本和环境开关；做成维护者可重复执行的固定流程。
- **备份与恢复。** 当前数据库档位的恢复历史很短。建立定期导出和一次恢复演练，把步骤写进上线自查文档。
- **导出自己的数据。** 用户能导出自己的训练记录。
- **监控与告警。** 提供方错误率、降级次数、预算触顶、数据库连接异常能主动通知维护者，而不是事后看日志。
- **性能实测。** 按说明书第 10 节的指标在真机上实测并记录。
- **计划卡收尾。** PL-4：每个用户只有一个生效计划。
- **主动周报。** 周报摘要已能生成；推送默认关闭。开启前要先为实例配置定时触发方（仓库不附带），并等通知渠道和用户设置就绪。
- **可维护性。** 拆分过大的组件和教练编排主文件；合并两处仓储目录；评测工具移出生产源码目录。随相关功能改动顺带做，不单独立项。

## 8. 阶段 5 — 扩大规模前的门槛

不排日期。出现对应触发条件时再启动，接缝见说明书第 7 节的表。

| 触发条件                         | 要做的事                                                       |
| -------------------------------- | -------------------------------------------------------------- |
| 部署超过一个服务实例             | 限流与配额计数改用共享存储                                     |
| 模型费用需要按人控制             | 按用户的调用与费用配额，必要时与付费档位挂钩                   |
| 数据量或连接数接近当前档位上限   | 数据库升档，备份与恢复策略随之调整                             |
| 准备开放注册                     | 邮箱验证、找回密码自助、滥用防护；公开运营所需的主体、协议与告知 |
| 定时任务耗时或数量明显增长       | 任务改走队列，保留现有幂等入口                                 |
| 有第二个人参与维护               | 完成 Beads 多人同步与恢复流程的验证；发布权限与复核分工成文    |
| 知识库语料明显变大               | 向量索引与重排序从默认关闭改为按评测结果启用                   |
